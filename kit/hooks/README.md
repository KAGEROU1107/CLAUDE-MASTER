# Hook and statusline integration — opt-in, not installed
Official reference: https://code.claude.com/docs/en/statusline ; https://code.claude.com/docs/en/hooks ; https://code.claude.com/docs/en/skills . Check the installed version, shell and actual JSON payloads before enabling.

Use a project-scoped absolute or documented project-directory path, not a global default. Preserve and merge existing statusline and hook settings after inspecting them. No full transcript or raw payload logging. The intended adapters: statusline reads host JSON, accepts only valid same-session metrics, writes private meter snapshot and prints a one-line status; UserPromptSubmit reads fresh same-session snapshot and emits a short checkpoint/allowance reminder; SessionStart checks for verified existing handover and reminds user to resume; PreCompact records an emergency pointer to existing verified state. No hook can invent a semantic summary or guarantee immediate execution of a skill. Statusline snapshots may lag until a response; explicitly check before heavy work. Use manual mode if statusline/hook unavailable. Do not enable until simulated and live tests pass. Existing user settings have priority; ask before changes.

The included `runtime.py` is a deterministic helper library for meters, thresholds, safe paths and checkpoint hashes. No actual hook adapter/settings activation is shipped in this draft. Implement and test those in WP05 under the verified runtime; use actual provider session ID, never generate a substitute for telemetry. If concurrent writers exist, add a per-session/path lock and test before activation. Path validation does not constitute a security sandbox against a hostile concurrent filesystem actor.
