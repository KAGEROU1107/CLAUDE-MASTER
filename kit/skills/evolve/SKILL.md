# EVOLVE

Input: evidence-backed learning or observed friction. Output: versioned improvement or reviewed proposal.
Check EVOLUTION_POLICY and authority first. One bounded useful improvement per milestone by default; prioritize actual user task. Candidate includes trigger, source, affected behavior, baseline, proposed narrow diff, scope, cost/quality goal, risk, tests and rollback. Reuse existing skill/native feature if adequate. Ordinary non-sensitive project Markdown/preferences and validated knowledge: capture prior version, apply safe in-scope change, verify readback and log automatically. For skill or executable change, create private sandbox candidate; define description/trigger, inputs/outputs, dependencies, limitations, test cases and removal plan. Test normal/edge/adversarial cases and compare baseline. States OBSERVED→CANDIDATE→EXPERIMENTAL→VALIDATED→ACTIVE or APPROVAL_REQUIRED; rejected and deprecated retained with reasons. Protected core instructions, settings/hooks, installation, permission expansion and active skill promotion require exact approval unless narrowly preauthorized where policy permits. Do not rewrite bootstrap or push upstream as a side effect; route verified upstream kit defects to `skills/contribute/SKILL.md` under `core/UPSTREAM_POLICY.md`. Regressions restore prior verified revision and log. Reduce duplication/context rather than inflate files. No hidden retraining or background operation claims.
Acceptance: meaningful evidence, precise diff, reversible path, scope-safe activation, no fabricated savings.
